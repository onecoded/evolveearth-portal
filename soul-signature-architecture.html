How the Image Lives On-Chain (Not a Link)

The core technique: the smart contract stores the SVG image as a base64-encoded data URI directly in contract storage. The tokenURI() function constructs and returns the full metadata JSON — including the image — without ever calling an external server.

// Solidity — Soul Signature NFT (ERC-721) // Image lives IN the contract. No IPFS. No AWS. No links to break. function tokenURI(uint256 tokenId) public view override returns (string memory) { SoulData memory soul = soulData[tokenId]; // Build the SVG directly from on-chain trait data string memory svg = _buildSVG( soul.vataPct, soul.pittaPct, soul.kaphaPct, soul.dominantChakra, soul.seals, soul.sadhanaPoints ); // Encode image as base64 data URI — no external host needed string memory imageURI = string(abi.encodePacked( "data:image/svg+xml;base64,", Base64.encode(bytes(svg)) )); // Build full metadata JSON — also fully on-chain string memory json = Base64.encode(bytes(string(abi.encodePacked( '{"name":"Soul Signature #', tokenId.toString(), '",', '"description":"Living healing passport on EvolveEarth",', '"image":"', imageURI, '",', '"attributes":[', '{"trait_type":"Vata","value":', soul.vataPct.toString(), '},', '{"trait_type":"Dosha Tribe","value":"', soul.tribe, '"},', '{"trait_type":"Dominant Chakra","value":"', soul.dominantChakra, '"},', '{"trait_type":"Tier","value":"', soul.tier, '"}', ']}' )))); return string(abi.encodePacked("data:application/json;base64,", json)); } // NFT evolves — new seal inscribed when retreat attended function inscribeMemorySeal(uint256 tokenId, string memory retreatId, uint256 timestamp) external onlyOracle { soulData[tokenId].seals.push(Seal(retreatId, timestamp)); emit SealInscribed(tokenId, retreatId, timestamp); // SVG auto-regenerates with new seal on next tokenURI() call }

This is the same pattern used by Nouns DAO, Loot, and Autoglyphs — the image is the contract. Your NFT survives any server going offline, any company going bankrupt, any IPFS gateway shutting down. It is permanent.

The Three-Phase Chain Strategy

Phase 1 — Launch on Base (Ethereum L2). Coinbase's L2 has near-zero gas fees, full EVM compatibility, massive wallet adoption, and mature NFT tooling. You build the on-chain SVG Soul Signature contract in Solidity, deploy to Base, and every OpenSea/Zora/Manifold integration works out of the box. TAO payments route via a bridge.

Phase 2 — Mirror on Solana. Once the community has momentum, deploy a Solana version for the Web3 native users who live in that ecosystem. Solana's speed and near-zero fees make it ideal for the high-frequency actions: daily oracle pulls, sadhana logging, micro-payments to practitioners.

Phase 3 — Migrate to Bittensor EVM Layer. When Bittensor's planned EVM-compatible layer launches, migrate treasury and governance there for full TAO-native integration. By then your community is large enough to bring your own users to a new chain.
